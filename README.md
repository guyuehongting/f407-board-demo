# f407 大绿板 —— STM32F407VET6 屏幕 + 板载按键

一块 STM32F407VET6 开发板（绿色的，就叫它大绿板），配上 1.8 寸 ST7735S SPI 屏，
丝印看不清、原理图没有，**引脚全靠现象反推出来的**。

这个仓库记录了最终结论、可用的驱动代码，以及「怎么一步步问出引脚」的过程。

```
SCK=PB10  SDA=PC3  CS=PC15  DC=PC14  RES=不接  BLK=3.3V
板载 5 键 = PD10 PD11 PD12 PD13 PD14（高电平有效）
SPI2  /64 = 656kHz   MADCTL=0xC0
```

## 一、硬件

### MCU

| 项目 | 值 |
|---|---|
| 型号 | STM32F407VET6（LQFP100，**无 Port F / Port G**） |
| 时钟 | HSI 16MHz → PLLM=16 / PLLN=336 / PLLP=2 / PLLQ=7 → 168MHz |
| 总线 | AHB 168 / APB1 42（定时器 84）/ APB2 84（定时器 168） |

### 屏幕：ST7735S 1.8" 128×160，8 脚模块

| 模块丝印 | 接到 | 说明 |
|---|---|---|
| VCC | **3.3V** | 别接 5V |
| GND | **GND** | |
| SCL / SCK | **PB10** | SPI2_SCK（AF5） |
| SDA / MOSI | **PC3** | SPI2_MOSI（AF5） |
| CS / CE | **PC15** | 片选，低有效，程序里一直拉低 |
| DC / A0 / RS | **PC14** | 命令=低 / 数据=高 |
| RES / RST | **不接** | 空着，用软件复位 `0x01` |
| BLK / LED | **3.3V** | 背光（想调亮度改接 PB8 做 PWM） |

实际焊 7 根线，RES 空着。

### 板载 5 个按键

| 按键 | 引脚 | 静止 | 按下 |
|---|---|---|---|
| KEY1 | **PD10** | 0 | 1 |
| KEY2 | **PD11** | 0 | 1 |
| KEY3 | **PD12** | 0 | 1 |
| KEY4 | **PD13** | 0 | 1 |
| KEY5 | **PD14** | 0 | 1 |

板上有**外部下拉电阻**，按键把脚接到 3.3V，所以是**高电平有效**。
配置用 `GPIO_MODE_INPUT` + `GPIO_PULLDOWN`。

> 另外说明：这块板上还有 4 个我自己手工接的按键（PE2~PE5），
> 跟板载这 5 个**完全无关**。实测按板载键时 PE2~PE5 一个都没动。

## 二、快速开始

### 主程序：`f407大绿板.c`

一个文件搞定屏幕 + 按键，不需要改 Keil 分组，不需要动 CubeMX。

1. 把 `f407大绿板.c` 覆盖到工程的 `Core/Src/main.c`
2. 编译烧录
3. 串口 115200（PA9=TX PA10=RX）可选，不接也能看屏幕

屏幕上会显示一个 5 键状态面板：

```
┌──────────────────────────┐
│  F407                    │  ← 深绿顶栏
├──────────────────────────┤
│ PD10 ▓▓▓▓▓▓▓▓▓▓          │  ← 松开：浅灰边框 + 暗灰条
│ PD11 ██████████          │  ← 按下：亮绿边框 + 亮绿条
│ PD12 ▓▓▓▓▓▓▓▓▓▓          │
│ PD13 ▓▓▓▓▓▓▓▓▓▓          │
│ PD14 ▓▓▓▓▓▓▓▓▓▓          │
├──────────────────────────┤
│ 007                      │  ← 累计按下次数
└──────────────────────────┘
```

功能：
- 按下哪个键，那一行边框和状态条变亮绿
- 左下角累计按下次数（3 位）
- 长按 800ms，状态条闪一下黄
- **长按 KEY5 满 3 秒 = 重新初始化屏幕并重绘**（花屏自救，不用按复位键）
- 串口同步打印 `[KEY] KEY1 PRESS` / `RELEASE` / `LONG`

### 文件一览

| 文件 | 作用 |
|---|---|
| `f407大绿板.c` | **主程序**：屏幕驱动 + 5 键驱动 + 界面演示，单文件 |
| `probe/main.c` | 按键引脚探测程序：不知道按键在哪时用它扫出来 |
| `probe/怎么看结果.md` | 探测程序的结果解读 + 排查表 + 本次实测日志 |
| `keys/main.c` | 单独的按键驱动（不含屏幕），引脚已配好 |

## 三、三个必须记住的坑

这三个坑每一个都让屏幕白屏过，记录下来免得以后又踩。

### 坑 1：`TFT_Cmd()` 会把 DC 拉低且不恢复

发命令时 DC 必须低、发数据时 DC 必须高。`TFT_Cmd()` 只负责「拉低 DC + 发一字节」，
**结束后 DC 停在低电平**。

所以 `0x2C`（写显存）之后发像素之前，必须自己 `DC_HIGH()`：

```c
TFT_Cmd(0x2C);
DC_HIGH();          /* ★ 漏了这一行，42768 个像素字节全被当命令解释 */
```

漏了会怎样：屏幕永远只有花屏，永远出不了纯色。

### 坑 2：CS / DC 千万别接反

接反的表现非常特别：

- **命令能进去**（屏幕会闪一下）—— 因为无参数命令两个脚怎么接都能送到
- **数据进不去**（填色一点不变）—— 因为像素数据需要 DC 在正确的脚上

口诀：**命令通 + 数据断 = 被当 DC 翻转的那根其实是 CS**。

正确是 `CS=PC15`、`DC=PC14`。

### 坑 3：RES 悬空会让面板自己复位

这块屏的 RES 没接。悬空的 RES 会被噪声拉低，面板跑几秒就自己硬复位 → **常白屏**，
而且按 MCU 复位键也没用（因为 MCU 好好的，是面板被复位了）。

判断方法：**看串口还在不在打点**。还在打 = MCU 活着 = 面板被复位了。

解法是把「可能是 RES 的那一批脚」全部配成**输入 + 上拉**：

```c
gi.Mode = GPIO_MODE_INPUT;
gi.Pull = GPIO_PULLUP;
```

用几十微安的弱上拉把 RES 钉在高阻高电平。

> **为什么不用推挽输出高**：PE2~PE5 是按键，一按就是直接对地短路，推挽输出高会烧；
> PB13 是电机方向脚，推挽输出高可能把电机驱动打开。
> 输入上拉只有几十微安，既能给 RES 确定电平，又绝不会短路。

## 四、按键引脚是怎么找出来的

不知道按键接在哪，就别猜。写个程序让它自己招。

`probe/main.c` 的思路：把 74 个候选脚全部配成「输入 + 内部上拉」，
然后盯着谁偏离静止电平。

### 为什么判据是「偏离」而不是「变低」

| 按键接法 | 静止 | 按下 | 能抓到吗 |
|---|---|---|---|
| 一端接 GND（最常见） | 1 | 0 | ✓ |
| 一端接 VCC（本板就是这样） | 0 | 1 | ✓ |
| 没接东西的悬空脚 | 1 | 1（强上拉下稳定） | 不会误报 |

判据是「和基线不一样」，所以高低两种极性都能抓，不用先猜。
悬空脚在强上拉下稳定读 1，不会乱跳，所以不会误报。

### 三步流程

1. **STEP1 双极性探测** —— 每个脚先上拉读一次、再下拉读一次
   - 两次一样 → 有外部上/下拉电阻 → 最可能是按键
   - 两次不同 → 悬空 → 排除噪声源
   - 这一步只作提示，**不参与过滤**（靠内部上拉的按键也会被判成悬空）
2. **STEP2 采样静止基线** —— 手离开板子，记下每个脚的静止电平
3. **STEP3 监听** —— 20ms 扫一遍，连续 2 次偏离才算数（天然消抖 40ms）

### 本次实测结果

```
[STEP1] pins WITH external resistor (best candidates):
PB2=0 PB14=1 PD3=1 PD4=1 PD10=0 PD11=0 PD12=0 PD13=0
PD14=0 PE1=1 PE8=1 PE9=1 PE10=1 PE11=1 PE13=1 PE15=1

[KEY] PD10 PRESS  (idle=0 now=1)
[NEW] key #1 = PD10
...
[SUM] keys hit  : PD10(1) PD11(1) PD12(1) PD13(1) PD14(1)
```

`STEP1` 那一行其实已经把答案圈出来了：**五个连续的脚、静止全为 0**，
正是「外部下拉 + 按键接 3.3V」的典型特征。

顺带：`PD3=1 PD4=1` 有外部上拉但按不动，不是按键（大概是 I2C）；
`PE2~PE5` 根本没出现在列表里，说明它们没有外部电阻、纯靠内部上拉，
符合「手工接线」的特征。

## 五、常见问题

### 屏幕纯白，什么都不显示

按顺序查：

1. **串口还在打点吗？** 在打 = MCU 活着 = 问题在面板（复位 / 供电 / 接线）
2. **RES 处理了吗？** 见坑 3，必须用输入上拉钉高
3. **CS / DC 接反了吗？** 见坑 2，命令通数据断就是接反了
4. **`0x2C` 之后拉高 DC 了吗？** 见坑 1

### 屏幕是花屏，不是纯白

纯白 = 一个字节都没收到；花屏 = 收到字节但命令/数据分界错了。
所以花屏基本就是 DC 的问题（要么接反，要么没在 `0x2C` 后拉高）。

### 画面上下颠倒 / 左右镜像

改 `MADCTL_VAL`，四个值试试：`0x00` / `0x60` / `0xA0` / `0xC0`。

### 红色显示成蓝色

`USE_BGR` 改 1。

### 边缘有杂色 / 少几列

`X_OFF` / `Y_OFF` 试 2 / 1（1.8" 模块的可见区通常是 132×162 显存里的 128×160）。

### 按键没反应

1. `KEY_ACTIVE_HIGH` 是不是反了？本板是 1（高有效）
2. `KEY_PORT` / `s_key_pin[]` 对不对？
3. 用 `probe/main.c` 重新扫一遍，看那几个脚还会不会动

### 屏幕用着用着变白

长按 KEY5 三秒，程序会重新初始化屏幕并重绘。

## 六、一些数值，供参考

| 项目 | 值 |
|---|---|
| 整屏刷新一次 | 128×160×2 = 40960 字节，656kHz 下约 **0.52 秒** |
| 单行重绘（边框+状态条） | 约 3KB，**37ms** |
| 单个数字（scale 2） | 约 8ms |
| `TFT_Init()` 耗时 | 约 0.4 秒（两次 150ms 延时占大头） |

**这个速度意味着：绝对不能每帧重绘整屏。** 主程序的做法是静态部分只画一次，
按键变化只重绘那一行，次数只重绘变化的那一位数字。

> PC13/PC14/PC15 属于备份域，驱动能力只有 3mA，所以 SPI 必须降到 656kHz。
> 想提速先别动这三个脚。
